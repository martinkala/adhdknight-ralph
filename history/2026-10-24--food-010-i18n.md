# food-010 — Multilingual UI sk / cs / en (2026-10-24)

## Decisions
- msgids are English texts (food templates already used `{% translate %}` with English); sk and cs are
  translations, en `.po` has `msgstr = msgid` so the compiled `.mo` contains every msgid (freshness test).
- `core.middleware.LanguageMiddleware` (after SessionMiddleware): `session["language"]` → `django_language`
  cookie → `LANGUAGE_CODE` (sk). Django's `LocaleMiddleware` is not used (no Accept-Language, no URL prefixes).
- Login stores the API language in the session and the cookie; changing it on the account page
  (`POST /account/language/` → `PATCH /api/v1/user/settings`) does the same. Login / registration use Django's
  `set_language` view (cookie only).
- Dates: `food_date` filter (sk/cs `j. n. Y`, en `j M Y`); weekday / month names from Django's `date` filter
  in the active language. Decimal separator already came from the active language's formats.
- Core views use error-code maps with `gettext_lazy`; `api_client` fallbacks are codes (`login_failed`,
  `registration_failed`) instead of Slovak texts.
- `web_app/requirements-dev.txt` (babel) is installed by `test-food.sh` instead of `requirements.txt` when it exists.
- e2e: `E2E_LANGUAGE=cs|en` sets the language of users made by `user_factory`.

## Problems / lessons
- Default language changed from en-us to sk, so existing Django tests asserting English texts ("Saved",
  "0.5 l", severity titles) were updated to Slovak.
- Babel's `write_po` drops `Language` / `Plural-Forms` unless `catalog.locale` is set explicitly.
- Tests parse `.po` with a small built-in parser, so they do not depend on babel.
- Full e2e suite passes with `E2E_LANGUAGE=en` and `E2E_LANGUAGE=cs` (43/43 each); three tests asserting Slovak texts or the sk date were made language-neutral.
